# 文書の規約

[共通規約](../RULES.md)に加え、変更対象の実装とテストを確認する。

- README は利用と開発の入口とする。docs/index.md は構成とセキュリティ、manuals は操作、others は開発とCIを担当する。同じ仕様を複数箇所に書き写さず、正本へ相対リンクする。
- 設計・手順ページは app-base と同じく先頭に title と source、その後に同名のH1と役割を説明する一文を置く。source はリポジトリのルートから見た根拠ファイルまたはディレクトリを指定する。
- 1ページに主題を説明する図または実際の操作画面を1枚置く。画像は隣の _assets に保存し、代替テキストと作成元を残す。画面はテスト用のダミーデータで撮影する。
- データの行き先・権限・失敗後の挙動を具体的に書く。秘密情報、個人の保存先、実行していない検証結果を載せない。
- 文書間やソースへのリンクにはリポジトリ相対の参照を使う。編集後は `pnpm docs:build` でタイトル、根拠、画像と文書のリンクを確認し、図・操作・制限が実装と一致するかを目でも確認する。
